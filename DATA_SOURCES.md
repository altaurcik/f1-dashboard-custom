# Независимые источники для Live Timing

Проверено 9 октября 2026. Требование пользователя: только бесплатные варианты, без backend Formula 1 Dashboard и без демоданных.

## Результат

Для истории найден и проверен прямой источник F1, включая координаты и телеметрию. Прямой бесплатный тайминг подтверждён на активной сессии; полный **live**, включая координаты/телеметрию, без подписки пока не подтверждён. Нельзя обещать одинаковое покрытие архивного HTTP и текущего WebSocket.

Предлагаемый набор: прямой F1 для текущих доступных topics и архива; локальный архив для истории и сравнений; Jolpica для результатов; GeoJSON/OSM/FIA для географии. OpenF1 не является обязательной зависимостью и не подходит как гарантированно бесплатный live-источник.

## Driver comparison

Новая панель заменяет Telemetry и Best Lap Benchmarks. Источник её полей — уже поступающие
TimingData (LAST, BEST, gap, interval, lap counter/metadata), TimingAppData (stint/compound),
TrackStatus и RaceControlMessages (исключения). Средний темп, изменение gap и условная
оценка сближения рассчитываются локально, без нового сервера референса. В гонке используется
временной разрыв; в квалификации BEST-delta не выдаётся за расстояние на трассе.
История накопительная с момента открытия feed; полный архив не подмешивается в live.
Точные проверки и ограничения — PROJECT_MAP.md, расчёты — src/lib/driverComparison.ts.

## Что действительно проверено

[Машинный отчёт](docs/data-source-audit.json) записывает время, URL, HTTP-статус и фактические ключи ответа. Проверка запускается без аккаунтов и токенов:

```powershell
node tools/check-data-sources.cjs .cache/data-source-audit.json
```

- Прямой архив Singapore FP1 2023: SessionInfo — HTTP 200; двенадцать потоков `.jsonStream` — HTTP 206 с разбором JSON. Position.z и CarData.z успешно распакованы из base64/deflate; найдены X/Y/Z/Status и каналы 0/2/3/4/5/45.
- LapCount проверен на гонке: CurrentLap/TotalLaps есть. Отсутствие LapCount в практике не означает отсутствие поля в гонках.
- Календарь F1 2026, GeoJSON Singapore и результат Jolpica Singapore 2025 — HTTP 200 с корректным JSON. Jolpica вернул fastest lap Hamilton 1:33.808.
- MP3 радио из официального архива — HTTP 200, audio/mpeg.
- Двенадцать запросов OpenF1 к историческим данным в локальной проверке вернули 401: API сообщил, что во время live-сессии ограничен **весь** доступ, включая прошлые сессии. Веб-кэш мог отдавать старый успешный ответ; ориентироваться на фактический ответ backend, а не поисковую выдачу.
- [Предстартовая проверка прямого WebSocket](docs/anonymous-live-probe.json): 22 пилота и доступные timing topics, сессия Inactive; Position.z/CarData.z отсутствуют.
- [Проверка после старта](docs/anonymous-live-active-probe.json), 12:30:40 UTC: SessionStatus = Started; получены 35 обновлений TimingData, 4 TimingAppData и 1 TimingStats за 25 секунд. В snapshot есть также RaceControlMessages/TeamRadio/WeatherData/clock/status; новых Position.z/CarData.z нет и в snapshot их нет. Это подтверждает бесплатный реальный тайминг, но не живые координаты/телеметрию.
- Официальный SessionInfo текущей Sprint Qualifying 2026 доступен; Position.z, CarData.z, TimingData и WeatherData `.jsonStream` вернули 403 и до старта, и сразу после него. Читать текущий архив частями как замену live на этой проверке не получилось; это не гарантия отсутствия файлов в любой момент сессии.

Проверка читает только небольшие диапазоны архивов, не запускает replay и не подмешивает исторические записи в live-состояние. HTTP 200/206 подтверждает доступ к конкретному ресурсу, а не полноту сезона или live-потока.

## Покрытие полей экрана

`F1:` ниже — topic официального потока, а не сервер референса. Для архива эти же topics читаются из `.jsonStream`. Обозначения: **история** — ресурс проверен; **live проверить** — требуется проверка покрытия конкретного поля/события, даже если сам timing topic уже доступен. Значения идентификаторов и URL сессии брать из Index/SessionInfo, а не строить по неподтверждённым именам.

## Где альтернативы не дают равной замены

[Документация OpenF1](https://openf1.org/docs/) описывает `car_data/location`, `laps`, `position/intervals`, `stints/pit`, `weather`, `race_control`, `team_radio`, `drivers/sessions/meetings`. Это запасная схема нормализации, а не выбранный бесплатный live backend. Location примерно 3.7 Hz, погода раз в минуту; intervals только гонки. В практике gap/interval надо получать из лучших кругов. Mini-sectors в races не предоставляются. Радио начиная с 2026 часто отсутствует; API не восстанавливает неопубликованные записи. Нет полноценного ExtrapolatedClock, гарантированного текущего InPit/PitOut и готовой базы рекордов всех конфигураций. Личные лучшие сектора/круги требуют накопленной истории и учёта удалений.

[Тарифы OpenF1](https://openf1.org/) подтверждают бесплатную историю с 2023 и платный live €9.90/мес. В наши бесплатные варианты платный тариф не входит. Локальный probe дополнительно обнаружил ограничение архивных запросов в live-окне. Самостоятельный запуск OpenF1 не снимает ограничение первичного источника: [его ingestor](https://github.com/br-g/openf1/blob/main/src/openf1/services/ingestor_livetiming/real_time/README.md) требует F1TV token для live telemetry.

Jolpica не заменяет FP timing, погодные датчики, координаты или мини-сектора. F1/FIA публикации и локальный архив предпочтительнее для исторических benchmarks. Даже официальные страницы бывают устаревшими: старая справочная страница Singapore всё ещё содержит рекорд прежней конфигурации, а [актуальная статья F1](https://www.formula1.com/en/latest/article/what-makes-the-singapore-grand-prix-special-and-why-you-should-see-it.f9it2DEDEjL9ZEjvQIMRq) подтверждает Hamilton 1:33.808 в 2025. Сохранять layout, дату проверки и ссылку первичного результата.

## Состояние проекта и последовательность миграции

**Сделано:** инвентаризация, проверки независимых ресурсов, официальный URL радио, правильная семантика RAIN, правило происхождения данных в AGENTS.md. Автоматической миграции всего потока ещё нет.

**Остаётся:** рабочий live адаптер использует relay референса из `.env.local`; `/api/live-context` — его REST; локальные portraits/logos/GeoJSON с дополнениями и GLB получены оттуда. Локальный файл не становится независимым источником лишь потому, что перестал обращаться к чужому CDN. 2D geometry также обращается к MultiViewer; это отдельный сторонний сервис, а не полностью собственная география.

Порядок бесплатной миграции:

1. Прямой анонимный F1 → собственный collector. На реальной активной сессии проверить каждый topic и время последнего обновления, особенно Position.z/CarData.z. Отдельно проверить рост `.jsonStream` через Range/Last-Modified. Предстартовый 403 не достаточен для вывода о live.
2. Вести свой журнал topic/value/sourceTimestamp и snapshot; скачать завершённые сессии с официального архива. Различать режимы live/replay, не заполнять live архивными координатами.
3. Перевести `/api/live-context` на официальный Index и локальную историю. Для records завести записи с kind/session/layout/sourceUrl/verifiedAt; отсутствующий рекорд оставлять пустым.
4. Свой manifest трасс: circuit key, layout revision, GeoJSON, калибровка XY, pit lane, повороты и сектора с первичными ссылками. Сохранить лицензии базовых данных; заменить дополнения референса проверенными.
5. Портреты брать из прямого DriverList; логотипы и GLB заменить ассетами с установленным происхождением. Не терять согласованный визуал при замене транспорта/ассетов.
6. Отключить все домены backend/CDN референса и проверить экран/сетевой журнал. До этого не утверждать, что независимость достигнута.

Если бесплатный прямой источник не отдаёт live координаты/телеметрию, честный результат — неполный live и полноценный архивный replay. Оценка по мини-секторам допустима только с явной подписью и не заменяет реальную телеметрию. Полного бесплатного независимого источника для всех полей в live на этой проверке не найдено.
